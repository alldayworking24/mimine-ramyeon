# 미미네 · 매장 운영 관리

최상위 `index.html`이 매출·비용 흐름 중심의 새 화면입니다. 서버에서는 기존 미미네 계정으로 로그인하고 활성 사용자 권한을 확인한 뒤 실제 장부·상품·입금 데이터를 읽습니다. 운영 데이터와 미리보기 데이터는 분리되어 있습니다.

- 저장·수정·삭제·촬영·스캔·입고·내보내기 등을 일관된 SVG 아이콘과 짧은 이름으로 표시.
- 기간 선택은 홈 기준 아이콘으로 통일. 매출·지출 입력은 금액 옆 저장 아이콘만 표시하며 접근성 이름을 유지.
- 지출은 임대료·카드 대금 순으로 먼저 표시하고, 항목 → 사용처/내용 → 금액 순서로 입력. 카드 대금은 사용처 대신 카드사를 선택하며 금액을 누르면 전체 선택. 입금 사업 필터는 실제 사업 로고와 전체·미분류 아이콘 사용.
- 홈·장부·비교·예측의 매출 금액을 눌러 오늘 매출 입력. 금액 옆 저장 버튼과 키보드 높이에 맞춘 입력창. 금액 입력칸을 누르면 기존 금액 전체 선택 후 바로 교체.
- 홈 금액을 눌러 매출·비용 등록, 기간 조회 및 작년/직전/직접 지정 비교.
- 부드러운 일별 곡선과 날짜 상세, 작년 일매출 비교, 기록 기반 월말 매출 추정.
- 홈: 오늘 금액, 같은 기간 올해·작년 매출과 차이(계산 부호 없음), 누적 비교 그래프, 일별 흐름, 현재 표시된 일매출 목록 합계.
- 홈 상단 정기 납부 알림: 3초 롤링, 완료·예정·일부 납부·기한 지남을 색상과 이름으로 구분. 임대료·카드별 결제일을 설정하고 주말·공휴일은 다음 영업일로 조정. 실제 비용 입력과 연결해 상태를 계산하며 이체를 실행하지 않음.
- 비교·예측: 분석 연도 선택, 연간 합계, 12개월 매출·비용·차이의 올해/작년/증감 목록, 월별 비교 그래프와 월→일 상세. 작년 연간은 12월 31일까지 전체를 포함하며 올해는 오늘까지 실제 기록만 합산.
- 우리은행 문자 수신 내역, 입금자명 자동 분류, 대상 제외, 월별·기간 합계.
- 상품 원가·수량·판매가·유통기한, 바코드 조회, 영수증 OCR 후 확인·일괄 입고.
- 상품·입고·가격·영수증·선택 비용은 한 DB 트랜잭션으로 저장하고 중복 요청을 차단합니다.

ZIP을 실행할 때는 압축을 모두 푼 뒤 Node.js 22 이상에서 `START-WINDOWS.cmd` 또는 `node app-server.mjs`를 실행하고 `http://localhost:4173/index.html`을 엽니다. 기존 계정으로 로그인하면 서버의 실제 데이터를 조회합니다. 실행용 `dist`가 포함되어 있어 단순 실행에는 `npm install`이 필요하지 않습니다. 자세한 방법은 `START-HERE.txt`를 참고하세요.

소스를 다시 빌드할 때는 Node.js 22 이상에서 `npm ci`, `npm run build`, `npm test`를 실행합니다. `npm run preview`는 휴대폰 폭 검증 도구도 엽니다. 빌드는 버전이 고정된 npm 패키지에서 로그인/OCR/바코드 엔진을 준비하고 `dist`를 생성합니다. 최상위와 dist의 index는 같은 내용입니다.

`index.html`은 항상 로그인·승인 확인을 거칩니다. 파일 주소(file/content)로 열면 동봉한 서버 실행 방법을 안내하며 자동으로 장부에 들어가지 않습니다. `?preview=1`이나 상위 화면의 가상 제공자는 운영 진입을 우회하지 못합니다. 저장된 로그인도 서버에서 사용자와 사용 승인을 확인합니다.

가상 체험은 ZIP의 별도 `mockup.html` 파일에서만 실행하며, 변경은 새로 열면 초기화됩니다. 일반 `npm run build`는 목업과 검증 도구를 `dist`에 넣지 않습니다. 기존 운영 사이트 https://mimine-ramyeon.netlify.app/ 는 이번 수정으로 배포·변경하지 않았습니다. 기존 계정·사진·분류·수신폰 관리 화면은 `legacy/index.html`에 보존되어 있습니다.

입금은 은행 직접 조회가 아니라 하루온종일 수신폰의 문자 전달 경로입니다. 키오스크/POS 매출 자동 수집과 상품별 판매 자동 차감은 연결되지 않았습니다. 사진 OCR 결과는 저장 전에 확인·보정합니다.

정기 납부 설정은 기존 `mimine_settings`의 `recurring_payment_rules_v1`에 로그인 사용자 권한으로 저장합니다. 실제 카드 결제일은 임의 추정하지 않으며 홈 알림의 설정에서 등록합니다. 2026·2027년 한국 공휴일을 포함했고 임시휴일 추가가 가능합니다. 계산·연결·검증 범위는 `PAYMENTS-2026-11-03.md`에 정리했습니다.
